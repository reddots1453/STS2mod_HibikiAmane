# M6 手动测试清单

> 状态规则：代码完成记为 `IMPLEMENTED`；只有完成本清单后才能记为
> `VERIFIED`。M6 新增 Model 类型和注册特性，必须完整重启游戏，热加载不足以
> 验证注册。

## A. 启动与隔离

- [ ] 完整退出并重启游戏，日志出现 `Framework self-tests passed`。
- [ ] 使用原版角色开局，章节列表、地图、UI、奖励和胜利流程无本 Mod 泄漏。
- [ ] 使用 MaidenSuccubus 开新局，`ms_dump` 输出 `acts=4`。
- [ ] 将 `FourthActRunAdapter.Enabled` 设为 `false` 的调试构建中，本角色也保持
      原版三幕流程（ACT4-4）。

## B. 第四幕入口与路线

- [ ] 输入 `ms_act4 holy`，能进入占位第四幕，Boss 标题为圣洁终点。
- [ ] 输入 `ms_act4 neutral`，Boss 标题为中立终点。
- [ ] 输入 `ms_act4 corrupt`，Boss 标题为堕落终点。
- [ ] 三条命令日志中的 Boss ModelId 各不相同（ACT4-2）。
- [ ] 不使用强制参数时，堕落区间为圣洁/中立/堕落分别路由到对应 Boss。
- [ ] 占位 Boss 能进入战斗、结束战斗，并且不会因缺失正式资源损坏存档。
- [ ] 第三幕自然结束后进入第四幕，而不是提前结束 Run。

## C. 保存与恢复

- [ ] 在第一至第三幕保存并读档，`ms_dump` 仍输出 `acts=4`。
- [ ] 在第四幕地图保存并读档，地图、Boss ModelId 和当前堕落值保持一致。
- [ ] 载入 M6 之前创建的本角色旧存档时，安全追加第四幕或输出明确错误，
      不崩溃、不覆盖存档。

## D. 内容承载接口

- [ ] 百科全书中原有测试卡、遗物名称与描述仍正常。
- [ ] 三路线卡牌奖励、欲望费用、随身、临时附魔、断罪、净化、圣言样本回归。
- [ ] `ms_dump` 能输出角色、堕落值/区间、欲望、满值标记、封印牌、控制实例、
      侵犯罪来源和第四幕开关。
- [ ] 原版小枝史莱姆 Adapter 的控制/侵犯/欲望意图回归通过。

## E. 固定种子与热加载边界

- [ ] 同一固定种子的奖励路线和敌人意图可重放。
- [ ] 修改数值或方法体后热加载有效。
- [ ] 新增/删除 Model、注册特性、存档字段或 Godot 节点后完整重启，且日志中
      没有未处理异常。
