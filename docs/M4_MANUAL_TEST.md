# M4 统一手动测试清单

## 测试前准备

- 必须完全退出并重启游戏；M4新增了卡牌、Power、意图类型和Harmony动态补丁，不能仅依赖热加载。
- 确认启用`MaidenSuccubus`与`STS2-RitsuLib 0.4.64`。
- 使用本Mod角色进入战斗并打开开发者控制台。
- 多敌人项目优先在至少有两名敌人的战斗测试。
- `enemyIndex`按当前存活敌人从0开始；可随时运行`ms_m4_state`确认索引、当前意图和内部状态。

## A. 启动与基础回归

- [ ] 启动日志出现`Escape projection patched ... concrete card effects`，且没有`Harmony failed`或未处理异常。
- [ ] 使用本Mod角色时，堕落条与欲望条正常显示，普通出牌、卡牌奖励和前置M0-M3机制没有明显回归。
- [ ] 使用其他原版角色进入战斗：不显示本Mod资源UI；敌人不出现控制、侵犯或欲望攻击意图；普通牌行为不变。

## B. 控制格挡判定

在一场本Mod角色战斗中按顺序执行：

1. `block 5`
2. `ms_control_apply attack 5 3 0`

- [ ] 结果为阻止控制；格挡从5变为0；玩家没有获得控制Power。

继续执行：

1. `block 4`
2. `ms_control_apply attack 5 3 0`

- [ ] 结果为施加3层攻击控制；原有4点格挡完全保留，没有受到生命伤害。

解除后继续执行：

1. `ms_control_release all`
2. `desire 8`
3. `block 5`
4. `ms_control_apply skill 5 3 0`

- [ ] 欲望8时仍被施加技能控制；5点格挡完全保留。

## C. 自定义控制意图UI与结算

执行`desire 0`、`ms_control_release all`，然后：

1. `ms_control_intent skill 5 3 0`
2. 观察敌人意图并结束回合。

- [ ] 意图使用控制图标，主数值为5，额外角标显示“技”和3；悬停文本说明格挡与挣脱规则。
- [ ] 若回合结束前格挡不足5，敌人行动后不消耗格挡并施加技能控制。
- [ ] 若重新测试时格挡达到5，敌人行动后仅消耗5点格挡且不施加控制。
- [ ] 控制意图执行后，敌人后续能恢复原版意图序列，没有卡死或“no valid state”异常。

## D. 挣脱投影与随身

施加`ms_control_apply skill 5 3 0`：

- [ ] 手牌中的技能牌名称变为“挣脱”，描述显示原牌、控制来源和当前挣脱值。
- [ ] 卡面出现半透明虚化与锁链覆盖；攻击牌保持原样。
- [ ] 挣脱牌仍显示原来的当前能量费用，但不显示原关键词和附魔。
- [ ] 打出1费挣脱牌：不执行原技能效果，只使对应来源控制从3降至2，牌进入弃牌堆。
- [ ] 费用被改变后，实际减少量与出牌时费用一致。
- [ ] 0费挣脱牌可打出但减少0；X费牌按实际投入能量减少挣脱值。

测试随身：

1. 先执行`portable 0`给一张手牌赋予随身。
2. 再按该牌类型施加控制。

- [ ] 随身牌不变为挣脱，名称、描述、关键词和原效果保持正常。

测试能力类型：

1. `card INFLAME`
2. `ms_control_apply power 5 2 0`

- [ ] 新加入手牌的能力牌变为挣脱，而攻击和技能牌不变。

## E. 多来源与解除生命周期

在至少两名敌人的战斗执行：

1. `ms_control_apply attack 5 2 0`
2. `ms_control_apply skill 5 3 1`
3. `ms_m4_state`

- [ ] 状态输出中有两个不同来源实例，分别为`Attack/2`和`Skill/3`。
- [ ] 打出攻击挣脱只减少敌人0的实例；打出技能挣脱只减少敌人1的实例。
- [ ] 一个实例归零后，仅对应类型恢复；另一个控制继续存在。
- [ ] 执行`ms_control_release 1`只直接解除敌人1的控制，而且不会让该敌人进入晕眩。

来源死亡：

1. 重新由敌人0施加控制。
2. 执行`kill 0`。

- [ ] 该来源的控制立即消失，受影响卡牌同帧恢复；其他来源控制不受影响。

挣脱奖励：

1. 对敌人0施加1层控制。
2. 打出至少1费的对应挣脱牌。

- [ ] 控制归零后，该敌人的当前意图立刻变为晕眩。
- [ ] 晕眩确实持续一个敌人行动，之后再恢复被替换前的原版意图。

## F. 侵犯

在有两名敌人的战斗中，让敌人0控制玩家，然后执行：

1. `ms_invasion_intent 6 1`
2. 结束回合。

- [ ] 非控制来源的敌人1也能使用侵犯意图。
- [ ] 侵犯造成6点普通攻击伤害。
- [ ] 永久牌组加入一张1费“精液”诅咒，卡牌带消耗。
- [ ] `ms_m4_state`的`curses`字段记录敌人1的模型ID作为来源。
- [ ] 敌人1随后进入并完整执行一次晕眩。
- [ ] `ms_m4_state`显示敌人1的`invaded=true`和`controlDisabled=true`。
- [ ] 同一敌人之后不再进入控制意图；多个敌人分别侵犯时会分别加入带各自来源的诅咒。
- [ ] 结束战斗、保存并重载，在下一场战斗运行`ms_m4_state`，诅咒来源仍然存在。

## G. 增加欲望意图

执行：

1. `desire 0`
2. `ms_desire_intent 2 0`
3. 结束回合。

- [ ] 意图使用独立的欲望攻击图标，悬停标题为“欲望攻击”，数值`+2`在自身图标下方居中；与同一行动的攻击、策略或其他附加意图并排时不重叠。
- [ ] 结算后欲望从0变为2。

原版Adapter样本（遇到`TWIG_SLIME_S`时）：

- [ ] 欲望低于5且该敌人本场尚未用过欲望攻击时，会插入一次欲望+1意图；同一敌人本场不重复使用。
- [ ] 欲望达到5后，该敌人可优先使用技能控制意图。
- [ ] 玩家被任意来源控制时，该敌人可优先使用侵犯；侵犯后遵守晕眩与本场禁用控制。
- [ ] 同一种子、同一操作顺序下，插入的意图顺序可重现。
- [ ] 不含Adapter的其他原版敌人，其AI序列保持原样。

## H. 最终日志与状态

- [ ] 全部测试后日志无未处理异常、递归溢出、资源找不到、`no valid state found`或Harmony报错。
- [ ] `ms_control_release all`后，所有牌立即恢复原显示/效果，`ms_m4_state`显示`controls=[]`。
