# 响木天音中文文本与悬停格式规范

日期：2026-09-07

适用范围：卡牌描述、卡牌侧栏悬停、关键字悬停、Power状态悬停、附魔与自定义静态悬停

需求边界：玩法语义与正式措辞以`DesignDoc.md`为唯一权威；本文只约束呈现和实现方式

## 1. 本地参考结论

### 1.1 原版

- 卡牌正文按实际结算顺序书写。独立效果通常使用完整句号并换行；条件、范围或同一效果的补充说明留在同一行。
- 伤害、格挡和其他动态数值使用SmartFormat变量，例如`{Damage:diff()}`、`{Block:diff()}`、`{Energy:energyIcons()}`，不手工拼接升级数字或能量图标。
- 机制名、状态名与牌堆区域使用`[gold]...[/gold]`。中文正文不在数字、量词和标点两侧加入英文式空格。
- 原生关键字由`CardModel`按照固定顺序自动插入正文：虚无、灵巧、保留、固有、不可打出位于正文前；消耗、永恒位于正文后。关键字悬停由`HoverTipFactory.FromKeyword`生成。
- 卡牌悬停按顺序聚合额外悬停、附魔、苦难、重放、充能球、格挡和关键字，并按悬停ID去重。正文中出现的生成牌或特殊状态应有对应卡图/Power悬停，而不是在正文重复长解释。
- Power的`description`服务于canonical模板、百科或卡牌来源悬停，必须是无需实例数据也能成立的完整静态说明。`smartDescription`服务于战斗中的可变实例，使用`{Amount}`或已登记DynamicVar显示当前值。

### 1.2 HornetMod 1.2.15

- 正式卡牌使用RitsuLib模板和SmartFormat；生成牌通过`HoverTipFactory.FromCard<T>()`显示侧边卡图，Power和关键字分别使用正式悬停工厂。
- 丝线使用内嵌资源图标；工具牌把`[gold]工具 {ToolDurability}[/gold]`作为独立末行，形成醒目的机制区。
- Power通常同时提供静态`description`与实例`smartDescription`；静态说明省略当前层数，实例说明再补入`{Amount}`。
- 大黄蜂中文文本中也存在少量同句堆叠、未着色机制词和旧兼容键，因此只作为RitsuLib实现方式参考，格式规范仍以原版为优先。

## 2. 响木天音规范

### 2.1 卡牌正文

1. 严格保留DesignDoc规定的效果、对象、时点、数值和结算顺序；格式整理不得补写或删改玩法语义。
2. 每个独立结算动作使用完整句子；两个完整句子之间换行。条件从句、同一动作的目标范围及“然后”链保持在同一行。
3. `透支：`等机制分支单独成行；原生和已注册关键字不在本地化正文中手写重复词条。
4. 动态数值一律使用DynamicVar和原版formatter；中文格式写作`{Amount}点`、`{Cards}张`，不写`{Amount} 点`。
5. 机制词统一使用金色：格挡、力量、敏捷、易伤、虚弱、脆弱、中毒、覆甲、消耗、虚无、保留、固有、手牌、抽牌堆、弃牌堆、消耗牌堆，以及本模组的欲望、堕落值、魔力增幅、魔装耐久、破碎、燃烧、断罪、净化、拘束、侵犯、透支、随身、沉底、圣言、附魔、挣脱和变身。

### 2.2 颜色与视觉层级

- `[gold]`：玩家可识别的规则术语、关键字、Power名、牌堆区域。
- `[purple]`：附魔、苦难或战斗中动态追加到卡面的额外规则文本；不得把普通基础效果整段染紫。
- `[red]`：危险值、剩余拘束值等明确负面强调；不用于普通伤害数字。
- `[blue]`：当前UI读数等中性动态值。
- `[img]...[/img]`：资源图标；必须使用稳定的`res://`路径。卡面正文不手写字体大小、居中或抖动标签，交给原版自动排版与文本特效设置。

### 2.3 卡牌悬停

- 原生关键字和RitsuLib注册关键字依靠卡牌`Keywords`自动产生悬停，不再额外创建同名静态悬停。
- `PowerVar<T>`由卡牌模板统一生成`HoverTipFactory.FromPower`静态悬停；对应Power的静态描述不得含未注入变量。
- 明确生成、变化或选择某张牌时，用`HoverTipFactory.FromCard<T>(upgraded)`显示卡图；升级预览必须继承来源卡升级状态。
- 附魔使用`HoverTipFactory.FromEnchantment<T>(amount)`；同一来源不要同时再创建内容重复的静态悬停。
- 透支等没有CardKeyword实体的规则使用一个稳定的静态悬停键，并在所有相关牌上复用。

### 2.4 关键字

- 标题只写机制名，不加括号、冒号或颜色标签。
- 描述先写直接结果，再写限制或例外；只描述该关键字本身，不重复来源卡效果。
- 卡面放置位置由`ModKeywordCardDescriptionPlacement`决定；需要显示的关键字必须同时启用卡面词条和悬停，纯运行时标记才可使用`None`。

### 2.5 Power状态

- `description`必须是静态、完整且不依赖实例字段的说明。除由模型显式注入的白名单变量外，不允许出现`{Amount}`、`{RemainingTriggers}`等裸占位符。
- `smartDescription`显示当前层数、剩余次数、持续回合或实际倍率。`{Amount}`由原版自动注入；其他值必须通过Power的`CanonicalVars`或显式`LocString.Add`提供。
- 多句Power说明保持紧凑段落，由悬停栏自动换行；只有列表或阶段式规则才手工换行。
- 可见Power必须同时具备标题和描述。隐藏运行时载体应在代码中明确`IsVisibleInternal => false`，不能以缺失本地化模拟隐藏。

## 3. 自动门禁

`scripts/ValidateLocalizationStyle.ps1`负责检查：

- 本地化文件可解析、标题/描述成对存在；
- 富文本颜色标签配对；
- 卡牌多句效果正确换行；
- 卡牌核心机制词已使用金色；
- Power静态描述不存在未获模型注入的动态变量；
- Power的`smartDescription`变量属于原版变量或逐Power登记的自定义变量；自定义变量还必须在实现中提供对应DynamicVar或显式注入。

该检查只验证格式与模板结构，不证明文本语义符合DesignDoc，也不替代游戏内悬停和卡面排版验收。
