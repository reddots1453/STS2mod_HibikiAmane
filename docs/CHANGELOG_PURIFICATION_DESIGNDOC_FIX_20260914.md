# 净化 DesignDoc 同步修复（2026-09-14）

## 问题

“净化”的旧实现只检查易伤、虚弱、脆弱和断罪四个写死类型，状态描述也把这四种写成封闭列表。当前 DesignDoc 要求遍历所有可叠加的负面状态；上述类型只是示例。

## 修改

- 每层净化在回合开始时重新遍历持有者当前的全部 Power。
- 候选必须是 `PowerStackType.Counter`、当前表现为 `PowerType.Debuff` 且层数不为0的状态。
- 按状态 ID 去重后等概率选择，保证概率与各状态层数无关。
- 正层负面状态减少1层；负数表示的可叠加负面状态向0恢复1层。
- `Single` 类型负面状态、增益和净化本身不进入候选。
- 净化触发后自身层数永久保留。
- 正式描述同步为：“回合开始时，每有1层净化，随机失去1层可叠加的负面状态。”

## 自动测试与回归门

- 使用不在旧硬编码列表中的原版“中毒”验证通用遍历与精确层数变化。
- 验证原版 `Single` 负面状态“不抽牌”不会被净化。
- 验证敏捷增益不受影响，净化触发后自身层数不减少。
- 结构验证禁止恢复四类状态硬编码，并锁定按状态 ID 等概率选择。
- 本地化格式契约锁定当前 DesignDoc 正式描述。
